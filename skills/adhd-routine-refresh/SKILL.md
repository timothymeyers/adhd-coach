The user needs to do a recurring task consistently but keeps losing interest and stopping. The ADHD brain needs **variation** to keep treating the task as new-enough to engage with. Give them **4 small variations** to rotate through — one per week, or per session, depending on the cadence.

> **Not medical advice.** Coaching only — not a substitute for diagnosis, therapy, or medication management. If the user is in crisis, point them to emergency services or a crisis line (US/Canada: **988** · UK/Ireland: **116 123** · <https://findahelpline.com>).

## Get the task

If the recurring task and its cadence aren't described, ask — what the task is, how often it needs to happen, and (optionally) what part of it feels most repetitive. One ask, then move.

## Design the 4 variations

Rules:

1. **Same core outcome.** Every variation still accomplishes the underlying purpose of the task. Rotation ≠ dilution.
2. **Different surface.** Each variation changes one axis so the brain registers "new":
   - **Location** — where it happens
   - **Format** — voice memo vs typing vs handwriting vs video
   - **Constraint** — time limit, word limit, structure
   - **Companion** — solo vs with a person vs with a specific playlist
   - **Order** — reverse the sequence, start with the hardest, start with the easiest
   - **Lens** — do it from a specific perspective (as a beginner, as a critic, as future-you)
3. **Each variation is fully specified.** Not "try a different location" — say *which* location and *why*.
4. **Sequence them.** Order the 4 so early ones are easiest to try. The first variation should require zero new setup.
5. **One should be genuinely weird.** A safe variation set gets stale too. One of the four should make the user laugh or wince a little — that's the one that resets the brain hardest.

## Format

**Rotation for: [task name]** (cadence: [weekly / daily / whatever])

1. **[Short label]** — [1-2 line description] · *changes: [axis]*
2. **[Short label]** — [1-2 line description] · *changes: [axis]*
3. **[Short label]** — [1-2 line description] · *changes: [axis]*
4. **[Short label]** — [1-2 line description] · *changes: [axis]*

End with one line: "**Rotate in order 1→4, then start over.** If any variation stops landing, drop it and I'll design a replacement."

## Anti-patterns to avoid

- Don't propose variations that quietly make the task easier and less useful (e.g., "skip the hard part"). That's not variation, that's decay.
- Don't propose 4 variations that all change the same axis. Spread them across different axes so the brain has multiple fresh signals to pick from.
- Don't over-explain. The user will read a paragraph per variation; they won't read an essay.
